# PRAD-8917 修复方案与任务

## 原因

原流程在 `ChangePassword()` 将账户状态提交为 `CREATED` 并返回后，才由 UI 关闭指纹签名。若在两步之间断电，启动恢复只看到有效的 `CREATED` 状态，无法识别已经变更的密码与仍开启的旧指纹签名授权。

## 修改方案

在 `ChangePassword()` 完成重复密码校验和旧密码解密后、写入 `CHANGING_PIN` 状态及重包账户密钥前，持久化关闭目标账户的指纹签名。删除 UI 成功路径中滞后的关闭调用。这样包括串口调用在内的所有 `ChangePassword()` 入口遵守同一顺序；输入校验失败不改变指纹设置。沿用现有指纹持久化失败时的断言策略，不增加新的恢复标记。

## 任务与验证

- [x] 核对修改密码、指纹设置和启动恢复的调用顺序。
- [x] 在账户重写前关闭目标账户指纹签名，并删除 UI 的事后调用。
- [x] 检查 Git 差异格式；WEB3 固件构建及 MPU 检查通过。
- [ ] 真机验证正常修改密码、输入错误及密码写入期间断电重启。

本地构建只能验证编译和链接；断电时序及设备上的持久化结果仍需真机回归。
