# 区分生产与开发版本的源码位置诊断

关联 Jira：[PRAD-8900](https://keystonejira.atlassian.net/browse/PRAD-8900)

## 背景与目标

断言携带源码文件和行号，新增注释行会改变行号常量，导致编译产物变化。开发排查又需要在设备上直接看到断言位置。本次按构建环境区分诊断信息，同时保留断言检查。

## 范围

统一 C 断言、错误日志、内存跟踪和参与固件构建的第三方诊断位置信息，不 revert 既有提交。Rust panic 在生产版本使用固定提示，开发版本保留位置。保留原有错误处理、重启倒计时和 panic 控制流程。

## 需求与场景

### Requirement: 生产断言不携带源码位置

生产版本必须保留断言失败处理，但不得由 ASSERT/assert 展开调用点的文件名和行号。

#### Scenario: 仅改变断言所在行号

- GIVEN 构建配置、代码逻辑及其他输入不变
- WHEN 仅在断言前增加注释或空行
- THEN 断言调用本身不因文件位置常量产生二进制差异

#### Scenario: 生产版本断言失败

- WHEN 断言条件不成立
- THEN 进入失败处理而不是继续正常业务
- AND 显示通用错误提示，不展示源码位置

### Requirement: 开发版本显示断言位置

开发版本必须保留断言位置，并在真机断言页面显示 file 和 line。

#### Scenario: 开发版本断言失败

- WHEN 断言条件不成立
- THEN 页面显示触发断言的文件与行号
- AND 保留原有重启倒计时行为

### Requirement: 两种断言入口行为一致

ASSERT 和 assert 必须遵循相同构建规则，每次调用只求值一次。

#### Scenario: 断言条件带副作用

- WHEN 执行 ASSERT 或 assert
- THEN 条件仅执行一次，条件成立时不进入失败处理

## 范围边界

- 不全局重定义编译器内建宏；用于协程状态、编译期标识符的行号不属于诊断，不予替换。
- 不处理调试符号、编译器隐式 panic 元数据或其他构建元数据，因此不承诺任意注释修改后整个固件 hash 一致。
- 不新增模拟器图形化断言页面；模拟器仅同步诊断日志规则。

### Requirement: 统一诊断位置规则

生产版本的显式源码位置诊断使用固定空文件名和零行号，或省略位置前缀；开发版本保留真实位置。不得改变错误返回值、内存分配方式或失败后的控制流程。

#### Scenario: 错误日志或内存跟踪调用位置变化

- GIVEN 生产构建且逻辑不变
- WHEN 仅移动诊断调用所在行
- THEN 诊断参数不携带变化后的行号
- AND 错误处理和内存操作保持原样
