# Monero 交易确认体验优化

## 背景与范围

优化 Monero 交易确认页的信息展示与请求处理体验。完整金额、输入输出明细、找零标记和 Payment ID 应清晰可读；不符合要求的请求应在进入确认页前提示失败。本规格描述用户可见行为与验收要求。

## 需求与场景

### Requirement: 金额完整且布局清晰

金额必须保留完整有效精度及 XMR 单位。长金额允许换行，后续内容随实际文字高度排列，不重叠、不截断。

#### Scenario: 查看长金额

- GIVEN 一笔包含长金额的有效 Monero 交易
- WHEN 用户打开 Details 页面
- THEN Input Value、Output Value 和 Fee 分别完整展示
- AND 金额与单位换行后不覆盖下一项
- AND 输入、输出列表中的金额同样完整可读

### Requirement: 明细顺序与标识清晰

输入输出明细按请求中的顺序展示，编号、金额、公钥或地址之间保持清晰间距。找零标记与所属输出关联，不遮挡金额或地址。

#### Scenario: 查看多个输入输出

- GIVEN 一笔包含多个输入输出和找零的有效交易
- WHEN 用户滚动查看 Details 页面
- THEN 每项内容独立排列，所有明细均可滚动查看
- AND Change 标记清晰归属于相应输出

### Requirement: 请求规模适合完整展示

整个请求累计最多包含 16 个输入和 16 个输出，输出数量包含找零。小型多交易请求保持支持；超过任一数量限制的请求在确认前拒绝，不进入确认页。

#### Scenario: 请求包含过多明细

- GIVEN 请求的累计输入数量或累计输出数量超过支持范围
- WHEN 用户扫描请求
- THEN 显示检查失败提示，不进入交易确认页

### Requirement: Payment ID 与所属输出关联

需要展示 Payment ID 的输出，应在其地址下方展示对应值，并保留完整内容。

#### Scenario: 查看带 Payment ID 的输出

- GIVEN 有效交易包含带 Payment ID 的输出
- WHEN 用户查看交易概览或详情
- THEN Payment ID 显示在对应地址附近
- AND 与相邻输出之间没有重叠或归属歧义

### Requirement: 确认前给出请求检查结果

进入交易确认页前完成可执行的请求检查。检查失败时显示错误提示，不进入确认页；有效请求继续正常确认和签名流程。

#### Scenario: 请求检查失败

- WHEN 导入的请求未通过检查
- THEN 显示失败提示且不进入交易确认页

#### Scenario: 有效请求完成签名

- GIVEN 请求通过检查
- WHEN 用户核对交易信息并完成确认
- THEN 正常执行签名并展示结果二维码

## 范围边界

- 本规格不包含内部审计细节、异常数据构造方式或诊断工具操作步骤。
- 辅助解析工具、fixture 数据、fixture 生成代码与本地调试开关不属于本次交付内容。
- 本次修改不改变历史交易数据。
