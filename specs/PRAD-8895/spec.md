# 钱包 UI 整理需求

关联 Jira：[PRAD-8895](https://keystonejira.atlassian.net/browse/PRAD-8895)

## 背景

钱包错误处理核心已通过 PR #98 合入。剩余 UI 整理独立 review，避免把页面公共实现调整与账户恢复逻辑混在一起。

交易页面重复维护容器和标题样式，备份确认按钮及 BTC 多签导出错误提示也存在可复用的实现。本次目标是减少重复维护，同时保持现有页面行为。

本文用于演练产品需求基线到研发交付的轻量流程。当前分支已有实现，因此这是补建的需求基线，不代表此前已经完成需求评审，也不代表现有代码已通过验收。

## 目标与范围

- 整理交易页面公共样式，保持各链页面必要的布局差异。
- 整理备份确认按钮的启用与禁用表现，保持确认条件和操作行为。
- 整理 BTC 多签导出的 SD 卡错误提示，保持错误类别、文案及关闭后的行为。
- 将本次 UI 调整与已合入的钱包错误恢复核心分开审阅。

## 需求与场景

以下场景作为待验证的验收条件，不是测试完成记录。研发方案应列出对应检查及未覆盖项。

### Requirement: 保持交易页面行为与布局

公共样式整理必须保持交易信息内容、显示顺序、操作入口及各链必要的布局差异。

#### Scenario: 查看交易详情

- WHEN 用户查看受影响的交易详情页面
- THEN 信息内容、显示顺序和操作入口与整理前一致
- AND 文字不重叠或截断，长内容仍可正常查看

#### Scenario: 查看 Monero 交易详情

- WHEN 用户查看 Monero 交易详情
- THEN 页面保留动态高度与底部留白

### Requirement: 保持备份确认条件

备份确认按钮必须保持原有确认条件，按钮状态必须与条件一致。

#### Scenario: 尚未满足确认条件

- GIVEN 用户尚未满足原有备份确认条件
- WHEN 显示备份确认按钮
- THEN 按钮处于禁用状态，用户不能继续

#### Scenario: 已满足确认条件

- GIVEN 用户已满足原有备份确认条件
- WHEN 显示备份确认按钮
- THEN 按钮处于启用状态，用户可以继续原有流程

### Requirement: 保持 SD 卡错误提示行为

BTC 多签导出必须保留缺少 SD 卡与导出失败各自的提示，以及关闭提示后的原有流程。

#### Scenario: 缺少 SD 卡

- GIVEN 设备缺少 SD 卡
- WHEN 用户执行 BTC 多签导出
- THEN 显示原有的缺少 SD 卡提示
- AND 关闭提示后保持原有流程

#### Scenario: 导出失败

- WHEN BTC 多签导出发生原有导出失败提示所对应的错误
- THEN 显示原有的导出失败提示
- AND 关闭提示后保持原有流程

### Requirement: 保持固件版本兼容

本次修改必须保持受影响的 WEB3、BTC_ONLY、CYPHERPUNK 配置可构建，相关页面和操作无回归。

#### Scenario: 构建并检查受影响版本

- WHEN 分别构建受影响的 WEB3、BTC_ONLY、CYPHERPUNK 配置并检查对应页面
- THEN 各配置构建成功
- AND 对应页面及操作满足上述适用场景

## 不在本次需求内

- 新增钱包业务能力或调整账户持久化、恢复与删除策略。
- 修改签名结果或签名失败的处理政策。
- 无关页面重新设计、字体资源更新及全仓库 UI 重构。

## 待确认事项

现有实现还包含 Solana、Stellar 签名入口复用公共签名方法。这可能改变 seed 读取失败时原有的 assert 行为，不属于纯 UI 整理。研发阶段需要单独说明差异，由负责人决定拆出或明确纳入需求；在此之前不能将其视为已批准的需求或已通过的验收项。
