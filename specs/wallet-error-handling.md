# 用户钱包错误处理与中断恢复

## 背景

原有 setup、forget password 等流程没有明确区分正常业务失败和系统异常，部分路径共用错误提示、返回逻辑及清理逻辑。

例如，setup 时用户输入助记词错误，应保留必要输入并允许修改后重试；但 `ModelWriteEntropyAndSeed` 或后续账户写入失败时，设备可能已经产生部分账户数据，此时必须终止流程并清理，不能再按普通输入错误返回上一步。forget 验证也必须区分“助记词不匹配”和“读取、派生、计算失败”，避免把系统异常误判为验证成功。

这类问题的风险包括：

- 错误被后续返回值覆盖，最终误报成功。
- 读取或计算失败被当作密码、助记词不匹配，甚至被当作匹配成功。
- 已写入部分账户数据后仍允许继续操作，产生不可恢复的不一致状态。
- 清理范围不明确，异常处理误删其他钱包。
- UI 返回到仍持有已清空敏感数据的页面，导致重复操作或崩溃。
- 断电后缺少可恢复状态，半成品账户被当作正常钱包使用。

## 目标

本功能仅覆盖用户钱包相关的错误处理，包括创建、导入、验证、forget、修改密码、Passphrase、删除钱包及 Wipe Device。

- 区分输入错误、不匹配等业务失败与读写失败、计算失败等系统异常。
- 业务失败保留安全重试所需的最少输入，不破坏已有数据。
- 系统异常立即停止后续操作，清理敏感缓存，并恢复或删除本次操作影响的数据。
- 清理限定于本次操作的目标账户，不误删其他钱包。
- 所有返回值和成功条件在使用点检查，避免错误被覆盖。
- 错误提示必须与处理结果一致；清理失败时禁止继续使用受影响状态。
- 涉及持久化修改的操作支持断电后继续恢复或清理。

## 非目标

- 不重构链业务、签名协议或 Rust/C FFI 架构。
- 不改变助记词、seed、PIN、Passphrase 的密码学算法。
- 不把所有底层错误合并成一个通用错误码。
- 不在普通钱包失败时执行全设备擦除。

## 错误分类

### 可重试业务失败

包括助记词格式错误、助记词与目标钱包不匹配、密码错误、重复密码，以及持久化写入开始前的低电量。

处理规则：

- 不修改或删除已有钱包。
- 保留安全重试需要的输入，其余敏感缓存及时清理。
- 返回当前流程可处理的失败信号，不显示成功结果。
- 只有明确的密码错误可以增加密码错误次数；读取、通信、计算失败不能伪装成密码错误。

### 不可重试系统异常

包括 SE/Flash 读写失败、密钥派生失败、持久化公钥信息损坏，以及账户数据已经修改后的最终验证失败。

处理规则：

- 立即阻止后续 Model 操作和页面导航。
- 清理 PIN、助记词、seed、Passphrase 及临时授权状态。
- 仅清理本次操作影响的目标账户。
- 在清理完成前保留恢复标记；清理失败或重启恢复失败时禁止进入正常钱包操作。

## 持久化状态模型

账户状态独立于加密账户数据保存：

| 状态 | 含义 | 重启处理 |
| --- | --- | --- |
| `UNKNOWN` | 空账户或没有状态标记的旧账户 | 使用旧账户有效性检查 |
| `CREATING` | 创建或导入尚未提交 | 删除目标账户 |
| `CREATED` | 账户数据已完整提交 | 保留账户 |
| `CHANGING_PIN` | 密码重加密尚未完成 | 删除目标账户，由助记词恢复 |
| `DELETING` | 删除钱包尚未完成 | 继续删除目标账户 |

`CREATED` 是账户创建和密码修改的最终提交点。只有账户 secret、public info、Passphrase 配置、名称图标及最终校验全部成功后才能写入。任何清理步骤失败时，不得提前清除恢复标记。

## 修改方式

### 统一 Model 错误出口

`src/ui/gui_model/gui_model.c` 将钱包失败拆成两类出口：

- `ModelWalletInputError()`：处理可重试业务失败，只发送流程失败结果。
- `ModelAbortWallet()` / `ModelAbortWalletWithNotice()`：处理不可重试异常，锁定后续钱包操作、关闭 USB、清理 SecretCache 和临时授权，并按 `cleanupRequired` 清理目标账户。
- `ModelFinishAbort()`：执行最终清理、退出当前账户并重启；清理失败只保留恢复标记，不允许回到旧页面继续操作。

`cleanupRequired` 表示失败后是否需要由外层清理目标账户，不代表账户是否发生过任何持久化修改。创建流程初始删除失败时不重复删除；已经持久化的 `DELETING` 标记由启动恢复处理。修改密码流程的 `modified` 仍表示是否越过持久化修改边界，并据此决定是否需要清理。

### 创建与导入

`ModelSaveMnemonicWallet()` 统一 BIP39 / SLIP39 的保存生命周期：

1. 检查电量、目标槽位、重复钱包和重复密码。
2. 首次 setup 在写账户前通过 `SaveSetupCheckpoint()` 保存 `SETUP_PHASE_WALLET_WRITE_PENDING`。
3. `CreateNewAccount()` / `CreateNewSlip39Account()` 在持久化写入前将目标账户标记为 `CREATING`，并通过 `cleanupRequired` 输出参数报告后续失败是否需要外层清理；仅在目标槽位成功清空后置为 `true`；清空失败时不重复删除原账户。
4. 每一步写入及校验立即检查返回值，原始失败不得被后续操作覆盖。
5. 全部数据成功后写入 `CREATED`，作为唯一提交点。
6. 首次 setup 在账户提交后同步保存 `SETUP_PHASE_DONE`，只有 checkpoint 成功才发送成功信号。
7. 修改后的失败只删除目标槽位；未修改的输入错误允许用户修正。

首次 setup 中断后回到创建/导入选择，不恢复缓存的 PIN、助记词或备份步骤。Add Wallet 中断后保留其他钱包，并回到正常解锁流程。

### 钱包名称和图标

钱包名称和图标属于同一个账户信息页，更新时先修改内存快照，再通过一次 `SaveCurrentAccountInfo()` 写入。写入失败时恢复内存快照，不能先持久化名称、再单独持久化图标。

### 助记词验证与 forget

- 只有明确返回“匹配”才允许继续 forget/reset。
- 正常不匹配作为业务失败提示用户重新输入。
- 公钥派生、存储读取和完整性校验失败作为系统异常处理，不能通过布尔取反变成成功。
- `FindAccountByXpub()` 在解析 JSON 前校验目标账户的 wallet data hash，损坏数据不得参与匹配。
- 取消、返回及失败时清除临时 reset authorization，后续操作必须重新验证。

### 修改密码

- 进入密码输入前展示三项风险确认，并检查电量至少为 20%。
- 旧密码错误、重复新密码、低电量属于未修改状态，不删除钱包。
- `ChangePassword(..., bool *modified)` 在写入 `CHANGING_PIN` 后设置 `modified=true`，明确持久化边界。
- 重加密开始后的失败发送 `SIG_WALLET_PASSCODE_ABORTED`，显示不可操作的失败页面和 10 秒删除倒计时，仅删除目标钱包并重启。
- 修改过程中断电时，启动阶段根据 `CHANGING_PIN` 清理目标钱包。

### Passphrase

- 派生或保存失败不能返回切换成功。
- 异常退出时清理临时 seed、密码及 Passphrase 缓存。
- Passphrase 操作没有修改基础账户数据时，不得删除基础钱包。

### 删除钱包

`DestroyAccount()` 在擦除数据前写入 `DELETING`：

- 账户页、SE 账户密钥、public info、Passphrase 和 wallet hash 全部清理成功后，才将状态改为 `UNKNOWN`。
- 任一步失败均保留 `DELETING`。
- `AccountsDataCheck()` 启动时发现 `DELETING` 会重复执行幂等删除，成功后才进入正常流程。

### Wipe Device

- 擦除指纹、SE、账户或 Flash 前先写入全局 wipe marker。
- 任一步失败均保留 marker。
- `PowerOnSelfCheck()` 在启动时继续完整擦除；恢复失败时阻止正常启动。

### UI 与本地化

- 可重试失败返回对应输入页面，并显示具体原因。
- 通用系统异常显示重启提示，不允许返回到已清理输入的页面。
- 密码持久化失败显示 `passcode_update_failed_title` 和删除倒计时。
- 新增文案全部使用语义化 key，定义在 `src/ui/lv_i18n/data.csv`，并提交生成的 `lv_i18n.c` 及所需字体文件。

## 场景与预期

| 场景 | QA 重点 | 预期结果 |
| --- | --- | --- |
| 创建钱包失败 | 助记词生成异常、内部数据不一致、账户写入或初始化失败 | 立即中止，不误报成功；清理本次敏感数据及不完整账户 |
| 导入钱包失败 | 助记词无效、重复导入、校验通过后的写入失败 | 输入问题允许修正；写入异常中止并清理 |
| 助记词验证 / forget 验证 | 不匹配、底层读取或计算失败 | 明确区分不匹配与异常；异常不得判定为成功 |
| forget 重置失败 | 验证后退出、覆盖账户时失败 | 清除临时授权；按恢复策略处理目标账户 |
| 修改密码失败 | 写入失败、最终验证失败、断电 | 不误报成功；未修改失败保留钱包，已修改失败清理目标 |
| 密码验证异常 | 密码错误与底层异常 | 仅密码错误增加次数；系统异常不当作密码错误或成功 |
| Passphrase 设置失败 | 派生或设置失败 | 不混用新旧状态；不误删基础钱包 |
| 删除钱包失败 | 部分擦除、清理失败、断电 | 保留 `DELETING`，重启继续删除，不影响其他钱包 |
| Wipe Device 失败 | SE 清理、账户清理或 Flash 擦除失败 | 保留全局 marker，重启继续擦除，失败时禁止正常启动 |

## 核心不变量

- `CREATED` 账户必须通过完整写入和最终校验。
- 非 `CREATED` 的中间状态不能进入正常钱包使用流程。
- 系统异常不能被解释成匹配、密码错误或成功。
- 清理只能作用于本次操作的目标账户，除非用户明确执行 Wipe Device。
- 恢复标记的生命周期必须覆盖全部持久化修改和清理步骤。
- UI 成功、失败提示必须与底层最终状态一致。

## Review 重点

- 检查每个错误返回值是否在被覆盖前处理。
- 检查创建流程的 `cleanupRequired` 仅在初始清空成功后设置；修改密码的 `modified` 应在持久化修改边界之后设置。
- 检查失败清理的账户索引是否来自本次目标，而不是当前登录账户的隐式状态。
- 检查所有成功信号是否只在最终提交后发送。
- 检查启动恢复失败是否会阻止后续账户初始化和 UI 进入 Home。
- 检查 BIP39 / SLIP39、首次 setup / Add Wallet / forget 是否共享一致的提交边界。

## 本地故障注入分支

故障注入代码只保留在 `fix/wallet-error-handling-test`，不会进入正式功能提交。串口命令格式为 `#device settings test:fault NN`；故障命中后自动清除，使用 `status` 查询当前故障，使用 `clear` 手动清除。

| 编号 | 注入点 |
| --- | --- |
| 05 | setup checkpoint 保存失败 |
| 06 | checkpoint 完成后、账户写入前失败 |
| 07 | 账户写入失败 |
| 08 | 账户写入过程中立即断电重启 |
| 09 | 最终 `CREATED` 状态提交失败 |
| 10 | `CREATED` 提交成功后立即重启 |
| 11 | Add Wallet 写入后失败并回滚目标账户 |
| 12 | 回滚目标账户时清理失败，保留恢复标记后重启 |
| 13 | 主动删除钱包时，写入 `DELETING` 后返回失败 |
| 14 | 主动删除钱包时，擦除部分账户页后立即重启 |
